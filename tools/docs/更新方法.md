# 课件笔记更新方法

本文件说明**有新课件时如何继续更新笔记**。可以自己按步骤操作，也可以把本文连同新课件一起丢给 AI 助手
（文末有可直接复制的提示词模板）。

---

## 一、目录结构

```
信号/
├── README.md                    ← 总索引（有新课件时更新"目录"表格）
├── 信号分析与处理-完整笔记.md      ← 整体笔记（由 make_combined.py 生成，勿手改）
├── 信号分析与处理.code-workspace  ← 推荐用它打开（含预览配置）
├── 更新方法.md                   ← 本文件
├── .vscode/settings.json        ← markdown 预览配置（图片显示相关）
├── 《信号分析与处理》xx.pptx      ← 原始课件
├── 笔记/
│   ├── 01-信号分析与处理概述/
│   │   ├── 00-索引.md            ← 该部分的章节索引
│   │   └── 01-xxx.md ...         ← 正式笔记
│   └── ...
├── assets/
│   ├── slides01/page-XXXX.jpg   ← 每张幻灯片的渲染图（长边 1600px）
│   ├── slides21/page-XXXX.jpg
│   └── slides22/page-XXXX.jpg
└── _tools/                      ← 处理脚本（可整目录删除，不影响笔记）
    ├── extract.py               ← 提取 pptx 文字/表格/备注/媒体（已容错畸形 XML）
    ├── hidden.py                ← 检测隐藏页并生成页码映射
    ├── formulas.py + omml.py    ← 提取 OMML 公式并转 LaTeX
    ├── upscale.py               ← 渲染图放大 + 转 JPEG
    ├── optimize_assets.py       ← 渲染图压缩到 1600px（让 markdown 预览流畅）
    ├── fix_img_paths.py         ← 归一化插图相对路径（幂等）
    ├── fix_table_pipes.py       ← 修复表格内破坏结构的裸管道符（幂等）
    ├── make_combined.py         ← 生成整体笔记（合并全部单章 + 目录 + 锚点）
    ├── make_cram.py             ← 生成抱佛脚速记（合并 3 篇 + 校验"无例题/无图片"）
    ├── verify.py                ← 单章笔记综合校验 + 覆盖率台账
    ├── verify_captions.py       ← 校验插图说明的 slide↔page 映射
    ├── verify_combined.py       ← 校验整体笔记的链接与锚点
    ├── scan_text.py             ← 文本损坏扫描（替换字符/异常重复字）
    ├── measure.py               ← 统计各章字数与插图数（精简前后对比）
    ├── compare_trim.py          ← 精简安全性：比对公式指纹与数值常量有无丢失
    ├── audit_lost_formulas.py   ← 对"消失的公式"逐条做 token 复核，区分排版合并与真丢失
    ├── audit_images.py          ← 盘点插图类型（供图片取舍决策）
    ├── orphans.py               ← 统计 assets 里被引用/未被引用的图
    ├── 笔记撰写规范.md            ← 笔记格式规范（AI 助手必读）
    ├── 精简规范.md               ← 精简轮次的质量口径与图片取舍规则
    └── pdf/、_extract/           ← 中间产物
```

## 二、新课件放置与命名

- 课件直接放到 `信号/` 根目录。
- `assets/` 子目录按**课件顺序**新建，如第四份课件用 `assets/slides04/`。
- 笔记目录用 `笔记/03-<章节名>/` 形式，编号保持与上课顺序一致。

## 三、更新流程（6 步）

### 第 1 步：探明课件结构

```powershell
# 幻灯片数、隐藏页、备注页
& python _tools\extract.py        # 需在 信号\ 目录下执行；输出 _tools\_extract\<课件名>\
& python _tools\hidden.py         # 输出 pagemap.json：幻灯片序号 ↔ PDF 物理页
& python _tools\formulas.py       # 输出 formulas.md：课件里可提取的公式 (OMML → LaTeX)
```

要点：
- `_tools/_extract/<课件名>/slides.md` 是**全文提取**（含表格、备注），`slides/slide_XXX.md` 是逐页文本。
- `hidden.py` 会报出被设为隐藏的幻灯片；**隐藏页不会被导出成图片**，必须记下换算规则。
- 若 python-pptx / lxml 报 `AttValue length too long`，说明课件里有畸形超长属性，
  `extract.py` 与 `hidden.py` 已内置容错处理，无需修改。

#### 公式能不能提取，取决于课件用的公式编辑器

这是整理公式时最容易踩的坑，先看清楚再动笔：

| 课件 | 公式实现方式 | 文字提取能否拿到 | 处理办法 |
|---|---|---|---|
| 2.1 节 | **OMML**（Word/PowerPoint 内置公式） | ✅ 能，`formulas.py` 可转成 LaTeX | 用 `formulas.json` 里的 LaTeX 撰写，同时配截图 |
| 01、2.2 节 | **MathType OLE 对象**（`Equation.DSMT4`） | ❌ 不能，只留存了一张图片 | **只能靠截图**，不要凭记忆补公式 |
| 内嵌 H5 演示页 | 网页控件（"不坑盒子"） | 导出后是空白占位框 | 按"内嵌交互演示、需在 PPT 中运行"如实说明，不要编造 |

`formulas.py` 会同时报出每页的 MathType 对象个数，便于判断某页公式是否只能看截图。
遇到 MathType 页，正确做法是：**打开对应 `assets/slidesNN/page-XXXX.jpg` 照抄**，符号以截图为准。

#### 关于"不坑盒子"占位框

部分页面的右侧是一个浅灰空框，写着"不坑盒子网页控件／请在安装了不坑盒子的 PPT 上全屏放映后查看"。
这不是渲染失败，而是课件本身把交互演示做成了网页控件。这类页没有可提炼的文字内容，
笔记中如实写明"该页为内嵌交互演示"，**必要时把该页截图剔除**（如 2.1 节很多公式页右侧就是这个空框）。

### 第 2 步：渲染成图片

**首选：PowerPoint COM 导出**（本机已装 Office；导出的是真正"最终态"，干净且快，152 页约 40 秒）：

```powershell
powershell -ExecutionPolicy Bypass -File _tools\ppt_export.ps1 -Pptx "课件.pptx" -OutDir "_tools\ppt_out"
python _tools\reexport_all.py      # 一键：全部课件导出 → 按 pagemap 重命名 → 转入 assets/ → 压成 jpg
```

> ⚠️ **为什么不再用 LibreOffice 转 PDF 再渲染**：LibreOffice 遇到 **MathType 公式对象 / Visio 对象**
> 时会把对象内部的多个显示单元全部画出来，造成**同一公式叠印多层**。本课程 6 份课件里
> 01 / 2.1 / 2.2 / 2.3 / 第3章 / 第4章 **都有这种页**（2.2 最严重，111 页含 OLE 对象）。
> 2026-10 这一轮先用 LibreOffice 渲染，2.2 的 page-0030/0060/0086/0148 出现叠印，
> 最后由同事发现、全部课件改用 PowerPoint 重导才解决。

若没有 Office，才走 LibreOffice 方案（注意上述叠印缺陷）：

```powershell
$node = "$env:LOCALAPPDATA\Programs\DeepSeek Harness\resources\runtime\primary-runtime\dependencies\node\bin\node.exe"
$cli  = "$env:LOCALAPPDATA\Programs\DeepSeek Harness\resources\app.asar.unpacked\dsh\node_modules\@deepseek-ai\libreoffice-kit\lib\cli.js"
& $node $cli convert --input "《新课件》.pptx" --output "_tools\pdf\04.pdf"
& $node $cli render  --input "_tools\pdf\04.pdf" --output-dir "_tools\slides04" --dpi 110
```

注意：
- 单次 `render` **最多 100 页**，页数多要按 `--pages 1,2,...` 分批，注意分批后文件名会从 `page-0001` 重新计数，
  要用返回 JSON 里的 `images[].page` 还原真实页码。
- 输出目录必须**不存在**，否则报 `EEXIST`。
- 返回 JSON 里有 `missingFonts`，若缺字体会影响排版，需要留意。

### 第 3 步：转 JPEG + 压缩归档

```powershell
& python _tools\upscale.py         # PNG → JPEG，长边压到 1600px（这一步必跑）
& python _tools\optimize_assets.py # 若已是 jpg，再压一次体积
```

如需指定新目录，先把渲染结果放进 `assets\slides04\` 再运行脚本。

> 尺寸权衡：2500px 原图单张约 290 KB，一个页面连续放十几张就上百 MB，
> VSCode 预览会明显卡顿甚至不渲染图片。压到 1600px 后单张约 135 KB，
> 公式下标与曲线细节仍然清楚（已目视核对）。
>
> 注意 PowerPoint 的 `Slide.Export` 直接产出指定尺寸的图（脚本里给了 1600×900），
> 所以正常情况下不需要再放大，只需转 jpg 压缩。

### 第 4 步：撰写笔记

阅读 `_tools/笔记撰写规范.md`，按其中的格式与插图要求撰写。要点复述：

- 笔记开头必须有 `> 来源：《课件名》，第 X–Y 页` 块。
- 插图相对路径为 `../../assets/slides04/page-XXXX.jpg`（笔记在 `笔记/<deck>/`，图片在根目录 `assets/`，
  相隔两层，所以是 `../../`）。**页码必须按第 1 步的映射换算**。
- 只嵌有信息量的图（波形、频谱、框图、公式推导、表格），纯文字页不嵌图。
- 课件备注用 `> 课堂补充：` 引出；`课堂演示` 页要写清现象与结论。
- 不要编造课件里没有的结论或数值。
- 每份笔记在 `00-索引.md` 中登记，并同步更新根目录 `README.md` 的"目录"表格。

### 第 5 步：自检

```powershell
python _tools\fix_img_paths.py     # ① 归一化插图路径（幂等，可重复跑）
python _tools\fix_table_pipes.py   # ② 修复表格里的裸管道符 |x(t)|（幂等）
python _tools\verify.py            # ③ 单章笔记综合校验 + 覆盖率台账（关键一步）
python _tools\verify_captions.py   # ④ 校验插图说明的 slide↔page 映射
python _tools\scan_text.py         # ⑤ 文本损坏扫描
```

`verify.py` 会一次性检查：

- 每个文件是否有一级标题与 `> 来源：` 块（含课件名与页码范围）；
- 全部插图链接是否真实存在、路径是否为 `../../assets/...`、页码是否越界、是否有说明文字；
- 各文件来源范围的**并集是否覆盖全部幻灯片**（报缺口与重叠）；
- `00-索引.md` 是否登记了所有文件、内部链接是否失效；
- markdown 表格列数是否一致、数学式里是否残留裸管道符。

只有 `verify.py` 打印 ✅ 才算完成。典型输出：

```
01-信号分析与处理概述   文件 9 个 | 插图 57 张 | 幻灯片 96 页 | 已覆盖 96 页   缺口: 无 ✅  重叠: 无 ✅
```

### 第 6 步：重新生成整体笔记

新增章节后，根目录那份 `信号分析与处理-完整笔记.md` 需要重新合成（不要手工改它，会被覆盖）：

```powershell
python _tools\make_combined.py     # 重新合并全部单章 → 整体笔记
python _tools\verify_combined.py   # 校验整体笔记的插图链接、目录锚点、单章链接
```

若新增了**第四份课件**，还要在 `make_combined.py` 顶部的 `DECKS` 列表里按同样格式加一行
（目录名、篇标题、课件说明），再运行上面两条命令。

## 四、给 AI 助手的提示词模板

> 我在 `信号/` 目录新增了课件《XXX.pptx》。请按 `更新方法.md` 的流程处理：
> ① 用 `_tools/extract.py`、`_tools/hidden.py`、`_tools/formulas.py` 探明幻灯片数、隐藏页、页码映射与公式可提取性；
> ② 转换并渲染成 `assets/slidesNN/page-XXXX.jpg`（注意单次渲染上限 100 页，分批后要还原真实页码）；
> ③ 依次跑 `_tools/upscale.py`、`_tools/optimize_assets.py`（清晰化后再压到 1600px，保证 markdown 预览流畅）；
> ④ 按 `_tools/笔记撰写规范.md` 撰写笔记到 `笔记/NN-<章节名>/`，**插图相对路径用 `../../assets/slidesNN/page-XXXX.jpg`**，页码必须按映射换算；MathType 公式页只能照抄截图，不要凭记忆补；**图片宁少勿多，交互演示页不要贴截图**；
> ⑤ 更新该部分的 `00-索引.md` 和根目录 `README.md` 的目录表格；
> ⑥ 依次运行 `fix_img_paths.py`、`fix_table_pipes.py`、`verify.py`、`verify_captions.py`、`scan_text.py`，把报出的问题全部修掉；
> ⑦ 运行 `make_combined.py` 重新生成整体笔记，再跑 `verify_combined.py` 校验（新增课件时先在 `make_combined.py` 的 DECKS 里加一行）。

### 如果要精简已有笔记

精简不是删内容，而是**砍冗余**。流程：

```powershell
python _tools\measure.py save      # ① 存基线（字数/插图数）
Copy-Item 笔记 _tools\_backup_before_trim\笔记 -Recurse   # ② 先备份，可回退
# ③ 按 _tools\精简规范.md 执行改写（图片取舍 + 文字压缩，红线不动）
python _tools\measure.py diff            # ④ 看每章降幅
python _tools\compare_trim.py            # ⑤ 列出精简后"消失"的公式/数值
python _tools\audit_lost_formulas.py     # ⑥ 逐条判定：是排版合并还是真丢失
```

第 ⑥ 步会输出"内容仍在 / 可疑"两类。**可疑项必须人工确认**：
本轮 120 条"消失公式"里，119 条属排版合并（`$$…$$`→行内 `$…$`），
1 条是箭头写法差异（`\to` ↔ `\rightarrow`），**实际丢失 0 条**。
若出现真正的公式丢失，立刻从 `_tools/_backup_before_trim/` 恢复该文件。

### 如果要新增/更新抱佛脚版

抱佛脚版（考前速记）的定位是：**只有概念、公式、性质、成立条件、易错点，没有例题/练习/图片**。

- 每份课件对应一篇：`笔记/00-抱佛脚版/NN-xxx速记.md`。
- 素材只从该部分的完整笔记里取，**不得编造课件没有的内容**；公式符号体系保持不变。
- 更新后运行：

```powershell
python _tools\make_cram.py     # 合并 3 篇 → 根目录《信号分析与处理-抱佛脚速记.md》并校验
```

`make_cram.py` 会拒绝任何"例题小节 / 解答段 / 自测 / 练习 / 图片引用"混入，
并打印各篇字数、表行数、公式数——抱佛脚版一旦被写成第二个完整版，这一步就会报警。

## 五、常见问题

| 现象 | 原因与处理 |
|---|---|
| `python-pptx` 报 `AttValue length too long` | 课件里被误塞入超长 HTML/ink 数据；用 `_tools/extract.py`（已容错）而非 python-pptx 直接读 |
| 渲染报 `Selected page count exceeds maxPages` | 单次超过 100 页，按 `--pages` 分批 |
| 渲染报 `EEXIST: mkdir` | 输出目录已存在，先删除或换名 |
| PDF 页数少于幻灯片数 | 存在隐藏页，查 `pagemap.json` |
| `missingFonts` 非空 | 系统缺字体，中文可能回退；可忽略但需目视抽查 |
| **VSCode 预览里插图显示不出来** | 依次排查：① 是否只打开了单个 md 文件而没打开文件夹（必须打开 `信号\` 或上层目录，或双击 `信号分析与处理.code-workspace`）；② 左下角是否处于"受限模式"，点它并**信任**工作区（受限模式会屏蔽预览里的本地图片）；③ 是否装了 Markdown Preview Enhanced，改用内置预览 `Ctrl+Shift+V`；④ 图片过大导致渲染失败，跑 `optimize_assets.py` 压到 1600px |
| 预览滚动卡顿 | 用分篇笔记一次只看一章；根目录的合并版含 269 张图，整份预览本来就重 |
| 笔记里插图路径写错 | 应从 `笔记/<deck>/` 出发写成 `../../assets/slidesNN/page-XXXX.jpg`（两层上溯）。跑 `python _tools\fix_img_paths.py` 一键归一化，再跑 `verify.py` 复检 |
